# 列表、搜索与统计

列表的一页可能只展示少量记录，却重复扫描整个目录、重新计数，或在排序比较中反复读取同一人物。观看统计也可能为取时间首尾而排序所有记录。本页说明如何减少这些工作，以及保留的筛选、排序和刷新规则。

| 入口 | 减少的工作 | 复用范围 |
| --- | --- | --- |
| 小说 `listBooks` 的阅读列表 | 从阅读状态出发统计符合条件的书籍，减少稀疏状态下的目录遍历。 | 当前请求的计数查询。 |
| 小说 `catalog` 的空筛选结果 | 为原分页查询追加恒假条件，省去再次扫描章节标题。 | 当前请求已固定的读快照。 |
| 小说 `listAuthors` | 复用已有静态汇总，省去后续作者页的三项目录聚合。 | 原汇总缓存与文件、WAL、来源和 schema 校验。 |
| 短视频 `listCollectionVideos` | 复用已读取的清单 `item_count`，省去第二次总数聚合。 | 同一读事务。 |
| 人物 `searchPeople` | 排序需要显示名时，每个人物对象只读取一次。 | 本次搜索的精确与模糊结果排序。 |
| 人物 `detailPayload` | 同一人物的后续页复用最近一份年份与筛选数组，使已有排序缓存可以命中。 | 原人物来源生命周期和作品引用预算内的一份成功结果。 |
| 收藏夹统计与指定文件夹列表 | 逐条归一化 ID 时复用已取得的文件夹对象，省去重复账号状态读取。 | 本次同步调用。 |
| 收藏与历史整页缓存 | 限制整页保留的作品引用，超限大页完整返回但不登记。 | 原账号、目录与作品查询版本下的缓存。 |
| 排行榜 `summaries` | 省去未使用的 SQL 去重计数，并在同次请求的相同连接上复用成员查询语句；公开总数继续由作品去重结果计算。 | 当前请求的摘要查询。 |
| 番号快速搜索前缀 | 限制已拥有作品记录与请求前缀的保留量，保留短前缀共享和 LRU。 | 原目录、封面版本下的前缀缓存。 |
| 观看历史的作品回退查找 | 缺少有效作品 ID 时，按需复用已经遍历的目录前缀。 | 本次历史索引重建。 |
| 短视频 `searchSuggestions` 的 LIKE 回退 | 建议栏填满后，跳过不再贡献结果的标签或标题查询。 | 当前请求。 |
| 短视频 `listVideos` 的回退计数 | 只依赖原表字段的筛选省去资料视图中的无关关联。 | 当前请求的总数查询。 |
| 短视频 `watchInsights` | 一次遍历累计观看指标和时间首尾，省去中间数组与时间全量排序。 | 本次统计重建。 |
| 访问统计 `statsPayload` | 没有地理筛选时，四条聚合省去地理表关联；省份选项先按原 IP 与存储类型去重。 | 当前请求的七条查询。 |

## 小说阅读计数

启用 `reading` 时，总数查询由 `novel_reading_state` 驱动，再按书籍主键关联 `novel_books`。阅读状态少于书籍时，计数不必逐本检查整个有效目录；普通目录仍从书籍表计数。

原有 `WHERE EXISTS`、查询参数和 `status = 'ok'` 条件保持。标题等字段的搜索、分类回退和作者去空格匹配也保持原规则；孤立状态及失效书籍不会进入总数。

阅读状态的书籍主键保证每本书最多匹配一次。是否进入阅读列表仍只取决于存在状态记录，不增加进度已解析、章节有效或状态类型的限制。

分页行查询、排序、`sourceRealm`、`listRevision` 和原始 offset 均未改变。计数、列表和汇总沿用同一请求的读快照；外部提交由后续请求观察，读取期间的版本变化仍按原协议处理。

私有稀疏样本包含 18,000 本书和 121 条状态。fixture 对照完整旧响应，并以实际计数访问次数验证状态驱动路径；排序行查询仍走原 SQL。

## 小说章节目录空结果

章节目录先在同一读快照内取得实际筛选总数。总数为零时，原分页条件追加恒假条件，使 SQLite 直接结束空页查询；仍准备语句、绑定原参数并执行，不跳过原输入校验、必需列检查或执行错误。非空查询的 SQL、分页、排序与锚点规则保持，公开书籍章节数继续来自原书籍字段，不用筛选总数替代。

私有两万章的未命中搜索样本中，总数查询仍访问两万份标题，分页查询的标题访问从两万次降至零；每请求的语句准备与执行次数保持。空章节、旧章节数、未知书籍、全目录模式、参数边界和外部提交另有完整旧响应对照；结果属于同一快照，下一请求才观察后续提交。

## 小说作者页汇总

作者分页沿用已有静态汇总缓存，只在数据库及 WAL 文件状态、来源、schema、扫描标记和读取版本保持时复用。首个冷页仍计算总数、分类和来源三项聚合；后续作者页省去这三项扫描，也不会清掉其他列表已预热的汇总。作者计数、分组、排序、分页与近期阅读仍逐请求读取，进度与恢复字段不进入静态缓存。

作者页使用可选的文件状态探测：探测失败或两个文件都无可确认状态时，继续原查询，不复用或登记静态结果。该回退仅处理文件状态探测，SQL 和解析错误仍传播；其他已有汇总与书籍页面的严格探测契约保持。读取期间外部提交、换库或状态变化也不登记旧快照；连接仍按原请求结束关闭。

## 短视频清单总数

读取清单时，`requireCollection` 已按当前本地用户取得 `item_count`。分页直接把该值作为 `total`，不再重复聚合清单成员与视频目录。

清单总数和分页行都在同一读事务中产生。并发新增不会让当前页的总数与行分别来自两个快照；刷新后的请求才显示新成员。

成员仍按添加时间、视频 ID 降序排列。有效游标优先于 offset，页大小、多取一行判断 `hasMore` 和下一游标规则保持；空清单与只有孤立成员的清单仍返回零总数。

原有可见性、状态和媒体类型规则保持，pending、missing 或图集记录不会因为此次优化新增排除条件。清单的本地用户归属校验、事务回滚和忙等待重试沿用原流程。

fixture 比较完整 offset 与游标响应，并验证代表性请求从四次读取减为三次。恢复旧总数查询的负控会触发读取次数断言。

## 人物排序显示名

人物搜索仍先完成名称匹配和已确认身份合并，分别收集精确与模糊结果。作品数降序决定优先级；只有作品数并列时，排序才读取显示名。

同一次搜索用人物对象作为键暂存显示名，精确与模糊排序共享这张表，空字符串也会复用。作品数已决定比较结果时不预读显示名，避免额外身份查询。

显示名比较仍使用默认 locale、数字排序和 `base` 敏感度。相等结果的稳定顺序、匹配来源 ID、精确结果优先和模糊结果数量限制均保持。

暂存表随本次调用结束释放。下一次搜索重新取得显示名，继续遵守既有资料更新、确认合并和连接替换的失效规则；身份循环和 SQL 读取错误仍向调用方报告。

## 人物详情分页

人物详情每个来源仅保留最近一份成功的年份与筛选结果，让后续 offset 页复用数组身份，命中已有排序缓存。筛选身份包含已读取的账号状态、可见性、筛选、年份及两个显示标志；排序、offset 和 limit 不改变筛选身份，原分页响应键保持。

年份与筛选数组的引用数同时计入既有 4,000,000 引用预算，每个来源最多保留一项。超限结果正常返回但不保留；分页呈现成功后才登记，错误不会留下半份结果。来源、账号、配置或资料变化按原归属与版本规则重新计算；未知筛选和其他列表调用沿用原处理。

每页仍计算动态 facets、取得原公开作品字段及预热封面。22,000 条合成作品连续十六页中，分类检查和排序标题读取从各 352,000 次降至 22,000 次，排序从十六次降至一次；动态收藏、进度检查及页内呈现次数保持。完整响应、年份边界、并列顺序、默认与空显示参数、更新与异常由实际详情、查询和呈现服务对照。

## 收藏夹与排行榜摘要

收藏夹统计及指定文件夹列表已取得当前账号状态，逐条归一化文件夹 ID 时直接传入这份状态中的文件夹对象。未知 ID、旧记录与默认文件夹仍沿用原归一化规则；不改变收藏扫描、筛选、排序、账号范围或缓存失效，也不增加跨请求缓存。

20,000 条合成收藏的完整文件夹请求中，账号条目读取从 20,002 次降至两次；两种实现仍各执行一次数据库版本查询。指定文件夹分页同样省去循环内的重复账号读取。这里减少的是同步状态访问，不能视为省去逐条 SQL；实际耗时收益较小。私有完整响应及异常对照、现有账号与文件夹验证覆盖切换、保存、目录更新和旧记录。

排行榜摘要不再计算无人读取的 `COUNT(DISTINCT ci.work_id)`，查询计划省去其临时去重树。每榜公开总数、已下载与未下载数量仍由后续查询的原作品去重结果计算；分组、更新时间、来源、排序和版本缓存保持。200 个合成榜单、50,000 条成员的完整响应一致，原有重复成员、首项归属、预热与分页检查继续执行。

成员查询语句仅在本次摘要读取中复用，不跨请求或连接保存。每个榜单仍取得当前连接并绑定原 ID；连接变化重新编译，空列表不提前编译，读取失败仍返回原已完成部分且不登记摘要缓存。200 个榜单的语句编译从 201 次降至 2 次，执行次数仍为 201 次；单个榜单和空列表分别保持 2 次和 1 次编译。私有完整响应、旧列类型、连接更换、DDL、关闭和失败重试均与原实现对照。

## 收藏与历史页缓存

收藏与历史页沿用原整页 LRU，最多六十四页，并共用 4,096 个页内作品引用的预算，足以保留六十四个普通六十四项页面。作品公开对象仍沿用原 4,096 条独立缓存。超限大页完整返回但不登记，也不挤掉普通页；重复大页需要重新组装。预算按引用数计量，不是堆内存上限。

账号、目录、作品查询版本变化时，原失效流程同步释放整页预算；筛选、排序、分页、预热顺序和公开字段保持。合成两万作品的八次一万六千项请求中，整页保留引用从 128,000 降至零，该样本缓存持有的不同公开对象从 127,022 降至 4,096。普通页、空页、原异常和重试、账号切换及实际路由响应另与完整旧机制对照；旧机制负控应超过页内作品引用预算。

## 番号前缀缓存

快速搜索按原目录和封面版本保留前缀结果，最多一百二十八个前缀桶、合计五万条已拥有的未下载作品记录；请求键超过一百二十八字符时不登记。命中仍优先最长可用祖先前缀，并更新 LRU；目录或封面版本变化时释放原登记。空桶也计入条目上限，预算按记录数计量，不是堆内存上限。

超过单次记录预算或请求键长度的结果完整返回，不截断搜索；淘汰后的前缀按原 SQL 重新查询。二千个不同空前缀的私有样本中，桶数从 2,003 降至 128；五个各一万二千条的来源保留量从六万条降至四万八千条。页内详情仍按原方式批量补齐，已保留的相关前缀继续共享同一作品对象；错误与版本刷新沿原流程处理。

## 观看历史回退

进度记录有有效作品 ID 时，继续直接读取作品；没有有效 ID 时，先检查文件仍是视频，再寻找目录中第一个包含该视频 ID 的作品。字符串 ID、共享视频的首项归属、最新进度与并列顺序沿用原规则。

一次历史重建按需要推进目录游标，命中时停在当前视频，后续回退复用已找到的归属并从原位置继续。只有需要更后面的目标时才继续遍历，不提前读取后面的作品或视频。视频数组空洞仍跳过，只为本次进度目标保存归属。

游标和临时映射不进入跨请求缓存。已有历史缓存继续按资料库、进度对象和进度版本刷新；保存进度、换资料库或账号后，沿用原失效流程重建。私有 20,000 作品、125 条回退进度的样本中，目录访问从 2,492,250 次减为 20,000 次；只有首项回退时仍只访问首项，全部作品 ID 有效时不遍历目录。

## 短视频搜索建议

LIKE 回退仍按作者、标签、标题的优先顺序填充建议，使用追加和去重后的实际条数判断容量。作者已经填满时跳过标签与标题查询；标签填满时只跳过标题查询。不足容量仍执行原查询，保留匹配范围、转义、条数和顺序。

需要标签时仍统计最多 160 条候选的全部标签，再按计数和名称排序。不能因已找到足够标签就提前停止统计，否则排名和相关作品数会变化。FTS 与索引作者的已有返回路径保持原样。

私有实际 SQLite 样本中，标签填满的一次建议查询由四次读取减为三次；作者填满时由四次减为两次，标签 JSON 解析由 160 次减为零。完整返回字段、大小写去重、媒体与作者范围及不足容量继续填充均与旧实现对照。

## 短视频列表总数

未命中已有快速分页且没有作者筛选、不筛作者删除状态、来源不是观看历史时，总数查询直接使用 `short_videos`，省去资料视图的十二个无关关联。筛选逻辑、绑定参数、分页行查询和排序保持；作者身份、删除状态及观看历史仍从原视图取得。关注条件继续使用原视图的空值回退表达式，保留旧列类型的比较规则。

10 万条合成视频的搜索样本命中 21,428 条，计数阶段的关联查找从 257,136 次降至零；分页 JSON 解析次数保持 96 次。关联记录密集时收益更明显，空关联表的收益较小；fixture 使用较小的实际 schema 样本核对完整旧响应、过滤、空值、分页及计数查询计划，不将一次计时作为通用延迟保证。

## 短视频观看统计

观看统计按原非空白时间规则选入记录，在一次遍历中累计观看数、完成数、进度均值和时长分组，同时取得时间首尾。首尾仍比较原字符串的 UTF-16 顺序，不转为日期、不去除返回值中的空格；进度值也按原记录顺序求和。

未知或非正时长仍不参与进度均值和时长分组，观看总数仍包含这些记录。时长阈值、完成判断、覆盖率及最终分组顺序保持。该阶段不再创建观看记录、进度比例和时间的中间数组，也不排序完整时间集合；已有资料库行投影和其他统计阶段保持原样。

统计仍由原 Worker 和目录版本缓存调度。热缓存不重算，显式刷新、状态或目录版本变化继续沿用原失效和请求归属规则；取消和停止流程保持。个人与健康统计的完整旧响应、字符串边界、混序小数进度与操作次数由私有 fixture 对照；原 Worker 与直接存储的完整响应仍互相核对。

10 万条均有观看时间的合成行中，观看对象访问从 60 万次减为 10 万次，五份 10 万项临时数组及完整时间排序均省去。当前 schema 的混合视频、图集与可见性样本也核对了完整个人与健康响应；实际收益取决于目录规模与观看覆盖率。

## 访问统计地理关联

访问统计没有省份或关键词筛选时，汇总、认证分组、每日统计和访客总数组合只读取 `access_daily`。地理表按 IP 主键至多匹配一行，省去这四次关联保持原聚合结果；空或不存在的地理记录也保留原规则。

省份分组、访客详情和省份选项仍读取地理表。出现省份或关键词筛选时，四条聚合恢复原关联，关键词仍覆盖原有 IP、地理字段和请求字段。省份选项沿原时间、认证与网络范围先对 IP 的原值和存储类型去重，再关联地理表；显式二进制比较保留旧库中大小写与尾部空格不同的 IP，不按旧列的 NOCASE 或 RTRIM 合并。查询顺序、参数、排序、分页及读取前的待写入刷新均保持，不添加统计结果缓存。

10 万条合成每日记录、5,000 个 IP 中，无地理筛选的全范围请求仍执行七条 SQL，地理主键查找从 70 万次减为 20.5 万次；带地理筛选时为 60.5 万次。省份选项自身从 10 万次查找降至 5,000 次。IP 重复较少时，额外去重可能增加耗时：10 万条记录均为独立 IP 的私有样本中，完整请求中位耗时增加约 3%，因此不承诺所有分布都更快。fixture 用实际初始化与旧库变体比较完整旧 JSON，核对查询计划、类型、空值、筛选、分页、地理更新、记录刷新及管理权限。原区域库、启动迁移和关闭检查继续执行，不读取实际访问日志。

这些优化沿用原 schema 与写入流程。小说作者页复用已有静态汇总，番号前缀限制已有缓存保留量；人物详情只在现有来源与预算内复用成功结果。阅读计数、观看统计、人物搜索暂存表和历史查找游标没有新增跨请求缓存；小说连接仍由原读取流程关闭，清单继续校验本地用户归属。
