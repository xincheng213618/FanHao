# 图库列表与分页

图库追加页同时检查列表版本和原始分页偏移。相册重扫或影视元数据变化可能把已显示条目移到尾部；继续按旧顺序的 offset 追加会漏项，按去重后的卡片数继续请求则可能反复取得重复尾页。

## 接口与版本

`GET /api/image-library/items` 保留原有筛选、排序和响应字段，并返回两个字段：

| 字段 | 含义 |
| --- | --- |
| `listRevision` | 不透明的变化标识，只用于比较是否相同。 |
| `nextOffset` | 规范化请求 offset 加上本次实际返回的原始条目数。 |

标识包含当前服务、索引发布与失效状态。影视额外检查元数据库连接、schema 和相关元数据表的版本：电影依赖电影表，电视剧与动画依赖剧集表，混合影视依赖两者。相册列表不依赖元数据库写入。漫画在已有公开条目映射中累计内容签名，并核对目录和数据库状态。读取前后来源变化时返回一次性标识，避免把旧结果标记成新的稳定版本。

图库数据库初始化会追加两行元数据版本记录，以及电影、剧集表各自的新增、更新、删除触发器。版本与业务写入在同一事务变化，支持其他连接提交；未提交写入和回滚不改变读连接看到的版本。独立视频封面缓存写入不会触发电影或剧集列表补齐；元数据表中的海报和其他字段更新仍会改变对应版本。

热态检查只读取 schema 和最多两行主键记录；schema 变化时重新核对版本表与触发器的 SQL 契约。旧数据库缺少记录、记录损坏或触发器缺失及被替换时，回退到本连接写入、外部提交和 schema 的整库检查，保证兼容性；此时封面缓存写入仍可能触发补齐。

标识不冻结整个翻页过程，也不提供数据库事务快照。客户端不解析其中的内容，不持久化新的 schema。旧接口缺少标识时，两端按 `scannedAt` 变化回退；无法检测同时间戳的变化。带标识与不带标识的页不能当作同一版本直接追加。

## 补齐与失败

Web 与 Android 都保存独立的原始已读取数量，显示数量只统计去重后的卡片。优先使用有效的 `nextOffset`，旧接口回退为请求 offset 加响应长度；达到原始总量或空页后停止续页。

追加发现版本变化时，丢弃该追加结果，从 offset 0 补齐已读取范围及本次目标页。每段最多请求 5000 条，并按服务器实际返回量推进，兼容更低的响应上限。段间版本变化最多重试三轮完整补齐；未成功时保留原列表与重试范围，显示可重试错误，不发布半份新列表。

请求绑定当前查询与页面所有者。查询、来源或模块变化后，旧成功、错误和完成回调不能更新新页面或写入其缓存。Web 阅读器出现时可以完成后台列表缓存，但不重绘阅读器、覆盖阅读状态或改变当前阅读位置。

Android 首次完整范围读取及版本变化后的成功补齐，按 offset 0 与当前目标范围键缓存聚合结果，保留分段加载后的冷启动离线恢复。普通追加页仍按原始请求页缓存；完整范围缓存缺失时可以读取已缓存的首段。尚未完成的在线补齐不会发布半份新列表，旧范围明确缩小时仍按新的目标重新读取。

聚合会创建新对象，需要在网络读取前确定账号范围并捕获缓存写入边界。首次待确认账号沿用已有状态端点确认；账号、来源或缓存代次随后变化时拒绝迟到聚合写入。已确认账号和切回游客后的范围恢复与初始游客遵循同一规则，不从请求完成时的当前登录推断旧结果归属。

## 服务端计算缓存

相册搜索按固定六个字段匹配，复用字段名数组，避免逐条创建 `Object.entries` 数组。相关度相同需要比较更新时间时，每个请求中的结果项最多解析一次日期；仍保留旧匹配分数、无效日期和名称并列规则，不增加跨请求搜索缓存。

按年份排序时，仅在比较器需要时解析记录的年份，同一次排序最多解析一次。仍取原回退字段中的首段四位数字，缺失或无效值按零处理，年份相同继续按原名称比较；只有一条记录时不解析年份。暂存结果随本次排序结束释放，下一请求重新读取当前字段，不添加跨请求缓存。20,000 条合成影视记录中，年份解析从 250,994 次降至 20,000 次；完整响应、分页、名称并列、元数据与原始年份更新均与旧比较器核对。

正式装配为电影、电视剧、动画和混合影视启用短期查询缓存，复用同一筛选、搜索与排序的完整结果、统计和选项，分页 offset 与 limit 不改变查询身份。每页仍核对索引与相关元数据版本；刷新、来源替换、版本变化或到期时重新计算。旧的可变索引调用者没有明确启用时保持逐次读取。

只保留最近一份查询，最多 30 秒、12000 行和 16 MiB 序列化权重；逐项计量，超过上限的结果正常返回但不保留。这是缓存预算，不是 JavaScript 堆内存上限。响应页与缓存对象分开复制，停机时释放缓存。

元数据批量读取失败时仍保留原有降级响应，但其版本会变化，读取期间发生变化的页使用一次性标识，不能进入稳定查询缓存。相册分类选项缓存只保留实际来源分类及“全部”项，不长期保留任意不存在分类的空结果。

电视剧元数据的公开批量读取省去列表不使用的 `json_ld_json` 原文；默认批量读取仍保留该字段，点查、详情及封面保持原路径，电影 JSON-LD 的身份校验也保持。两种批量语句共用原连接、schema 版本与一次列发现，首次使用各自语句时才准备，不新增结果缓存或逐次表结构探测。

私有一千组剧集、四千集的样本中，每组有 64 KiB JSON-LD 时，公开批量读取到 JavaScript 的原文字节从 62.5 MiB 减至零；零原文与 8 KiB 原文也核对完整响应及读取次数。缺列、额外列、DDL、封面类型、连接更换、原异常和失败版本仍由同一查询验证覆盖；默认原始批量结果与封面字节保持。

电视剧与动画冷列表在同一来源再次出现时，才为本次请求创建两张剧名规范化暂存表。首次出现的来源继续直接解析；后续按完整的已转换标题和本地剧名取键，只省去重复 NFKC、大小写与季集解析。每行原属性读取、字符串转换、合法性检查和分组键生成仍执行。不同分类、来源、元数据 ID 或本地季名不会仅因来源键相同而合并；详情调用保持原路径，临时表随本次调用释放。

10,000 集、200 组重复剧名的私有样本中，NFKC 规范化从 20,001 次降至 801 次，季集正则与字符计数各从 10,000 次降至 400 次；数据库与公开剧集对象读取次数保持。完整列表、原分组、分页、更新和异常顺序均与旧实现对照。10,000 个来源全部唯一时，不再创建原先保存 20,000 项的两张暂存表；同标题但不同 ID 与来源也不因标题相同而提前创建。代价是重复样本比立即创建缓存多解析各来源的首次出现；八轮私有完整请求中约多 1 ms，仍保留主要复用收益。计时受 GC 影响，只作诊断，不据此承诺所有目录更快。

## 漫画章节封面查询

漫画详情逐章读取首张已下载图片。读取连接分别保留作品与章节两条固定 SQL 语句，后续执行仍绑定当前作品和章节，不保存行结果。1,000 章的私有详情样本中，整个响应的 SELECT 编译次数从 1,005 次降至 4 次；SQL 执行和数据库文件检查仍各为 1,005 次。

每次读取继续检查数据库文件身份。连接关闭、文件替换或查询失败时释放两条语句；下次读取重新准备。外部 WAL 更新和 schema 变化仍由当前 SQLite 连接读取，新增列继续出现在 `SELECT *` 中。完整旧响应、参数边界、表重建重试及相同 mtime 文件替换由现有查找 fixture 核对。

## 套图封面选择与校验

选择压缩包封面时，先完成原路径过滤，再逐项计算提示词、层级和格式评分，只保留当前最高分候选，省去全部评分记录的排序。同分仍取原顺序的第一项；没有显式封面时沿用原回退，不改变抽取、生成或发布规则。50,000 张合成候选中，最高分一直不变的样本从创建 50,000 份评分记录降为一份，评分排序次数降为零；候选仍全部评分，不能据此推断真实压缩包的总耗时。

封面请求保存独立的字节基准，后续数据库 BLOB 用字节比较确认内容未变，省去重复 Base64 转换。其他字段仍沿用完整 JSON 比较，包括旧库的额外字段；空 BLOB、空值及历史文本值保持原处理规则。基准不与调用者共享可变存储，当前行的带偏移字节视图也按实际范围比较。

数据库、相册、源文件身份、生成版本和停机检查继续在原位置执行，数据库读取次数不减少。64 次热态合成封面请求中，64 KiB 与 1 MiB 两种样本的 Base64 转换均从 192 次降至零，字节复制减半；这是该校验与响应路径的操作计数，不是整个应用的内存上限。

## 压缩包图片清单校验

套图详情命中图片清单缓存后，仍按原位置核对数据库连接、完整索引行、文件身份与停机代次。标准 SQLite 行的 `images_json` 是不可变字符串时，直接比较原文；其他原始字段以完整 JSON 比较，保留列顺序和额外字段的变化检查，省去反复转义整份图片清单。历史非字符串值、额外 BLOB、访问器、代理与自定义对象沿用原整行序列化；两种记录格式切换时，仅在比较中复原已捕获的完整 JSON，保留原缓存命中规则。

两万张合成图片的热态分页中，三次索引行校验传入序列化的清单原文从 5,933,343 字节降至零；三次索引查询、两次异步文件检查、缓存容量与有效期保持，公开分页字段和图片顺序保持。清单响应仍按原规则序列化并计入 16 MiB 缓存预算；该预算不是整个进程的内存上限，小清单不承诺加速。

## 卡片复用

同一筛选、布局和稳定顺序下，普通平铺列表、Web 电视剧作品书架与西方作品人物书架保留旧卡片、图片节点、焦点和封面 observer。加载与错误只更新尾部控件；成功仅追加新 ID 或替换内容变化的卡片，替换时释放旧图片观察目标。加载期间禁用续页按钮，失败重试保持原请求范围。

Android 影视标题栏在同一频道和标题布局下保留内联搜索按钮，只更新数量、文字与辅助标签，避免翻页时丢失键盘焦点或重复绑定点击。频道、布局或搜索能力变化时按原有规则重建。

Android 普通列表追加保留旧条目引用，相同引用的已挂载项跳过 JSON 序列化；新引用仍比较内容，同 ID 内容变化时替换卡片，相同内容时更新保存的引用。加载下一页期间不计算不会用于跳过渲染的整页签名；完整刷新仍沿用原有比较。

Android 相册瀑布流沿用条目索引与列数分配，追加到既有列。列数变化、重排、删除、缺少稳定 ID 或客户端分组时仍使用完整重建。漫画分组与相册集合展开保留原有完整渲染规则，不把展开后的集合数用作服务端 offset。

## Android 本地缓存

查看指定服务的缓存统计时，响应与图片通过已有的 `baseUrl` 索引读取该服务的记录。空服务参数仍统计全库；响应版本过滤、历史条目的大小回退和最新更新时间规则保持不变。

首次打开缓存时，过期响应清理先读取主键。带当前版本标签的键直接保留；其他有效键读取原记录，仍按版本字段或键标签任一匹配的旧规则判断。检查与删除在同一读写事务内完成并等待提交，避免误删另一个页面的新写入；通常的当前版本记录无需克隆 JSON 正文，历史歧义键保留兼容读取。

缓存数据库沿已有升级流程升到版本 3，为响应和图片建立 `trimMetadata` 复合索引，不改写旧记录的 payload、Blob 或大小字段。写入后的容量巡检仍检查所有服务与账号，但完整格式只读取键、大小及访问时间，避免重复克隆响应和图片句柄。缺字段、零大小或特殊历史类型回退完整记录，保持旧大小计算与淘汰规则；这是兼容慢路径，不表示历史记录都已转为快速读取。

巡检的读取、排序、累计容量与删除在同一读写事务完成，并等待提交，避免其他页面的新写入被旧快照删除。600 条/120 MiB 响应和 2500 条/250 MiB 图片预算、访问时间排序及相同时间的主键顺序不变。升级被其他页面占用时沿原有失败路径返回；新连接收到版本变化会关闭并允许重试，不清空缓存来处理升级失败。

预览和预缓存图片在第一次异步读取前捕获服务与清空代次。清空指定服务仅使该服务的旧写入失效，全局清空使所有旧写入失效；旧下载仍可显示到原页面，但不能回填已清空的图片缓存。访问时间更新重新读取当前记录，避免恢复被删除的图片或覆盖较新的内容。图片写入等待 IndexedDB 事务完成后才返回成功；图片仍跨账号共享，JSON 响应仍按账号隔离。

## 验证与适用范围

```powershell
npm run verify:image-library
npm run verify:image-query
npm run verify:image-query-cache
npm run verify:photo-search
npm run verify:gallery-rendering
npm run verify:android-channel-rendering
npm run verify:android-cache
npm run verify:manga-lookup
npm run verify:archive-images
```

查询检查使用实际服务、合成索引和私有 SQLite，核对旧字段逐字节一致性、缓存预算及失效、重排、外部提交、连接替换、版本记录与触发器损坏回退及固定探测开销。两端浏览器检查使用当前客户端与完整 CSS、动态 loopback API 和合成图片，核对漏项补齐、封面缓存写入、服务器响应上限、重复尾页、账号范围冷启动缓存、失败重试、取消、搜索焦点与卡片保留。Android 命令先同步生成缓存引用，不安装或发布 APK。

缓存检查包含合成 IndexedDB 下的清空、迟到写入、访问更新和事务中止，以及私有 Chromium 的实际索引读取、完整统计结果对照和图片清空行为；不读取真实缓存。季集规范化另核对完整旧列表、跨分类与季名、未知元数据、属性及转换异常顺序，以及唯一、单项和重复来源的实际暂存表分配；旧规范化负控应超过解析预算，立即创建暂存表的负控应超过唯一来源的两张规范化暂存表零分配预算。电视剧 JSON-LD 检查对照公开列表、默认原始批量记录、详情和封面，覆盖旧库、DDL、连接更换及原异常；恢复旧公开批量读取应超过 JSON-LD 字节预算，原封面 BLOB 负控继续超过复制预算。漫画检查使用实际采集器 schema 与私有数据库；压缩包检查使用合成 ZIP、受控子进程及私有数据库，保留原生成、发送与停止验证。封面选择核对同分顺序、路径读取阶段、完整响应和记录；字节校验另覆盖内容或额外字段变更及共享存储变更。清单校验对照实际套图详情、旧类型、字段顺序、连接与记录格式切换及原异常；原整行序列化负控应超过清单原文字节预算。读取、解析、编译、评分记录、字节复制和序列化次数作为固定开销门槛，恢复旧算法应在相应预算处失败，计时只作诊断。临时目录清理与替换遵循[数据边界](../ai/safety.md)。

节点数量与计时只描述该私有 Chromium 条件；它们不证明真实资料库耗时或 Android 真机体验。正式服务、真实媒体和设备验收遵循[验证矩阵](../reference/verification.md)与[数据边界](../ai/safety.md)。
