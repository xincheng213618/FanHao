# 密码找回与操作记录

网页和 Android 共用管理员协助找回密码流程。注册仍默认开放，邀请码仍非必填；密码重置码与邀请码分别管理，不能互换使用。

## 帮用户找回密码

1. 管理员登录用户中心，打开「用户管理」，找到账号并选择「重置密码」。
2. 核实用户身份后，输入自己的管理员密码，选择「生成一次性重置码」。
3. 复制完整重置码并交给该用户本人。系统不自动发送邮件或消息。
4. 用户在网页或 Android 登录表单选择「忘记密码？」，输入用户名、重置码和新密码。
5. 成功后，该账号全部设备退出。用户使用新密码重新登录。

重置码以 `FHR-` 开头，随机部分为 192 位，区分大小写；前后空白自动去除。有效期 30 分钟，只能使用一次。用户名不区分大小写，重置码仅适用于指定账号。新密码要求与注册相同，为 10–128 位。

完整码只在本次生成面板显示，离开用户管理后不再保留；关闭面板不会撤销已经发出的码。丢失码时重新生成即可，旧码立即失效。管理员密码校验失败时不会生成码，签发时也会重新核对管理员角色、密码版本和发起会话仍有效。

生成码不会退出用户。真正设置新密码时，在同一事务中更新密码摘要、消费重置码、撤销该用户全部会话并写入操作记录。并发提交只允许一次成功，失败不会部分更新密码或会话。重置成功不自动登录。

以下情况会使待用重置码失效：超时、已经使用、重新签发、目标账号角色或停用状态改变，以及用户正常修改密码。停用账号不能签发或使用重置码；重新启用不会恢复旧码。

当前找回流程依赖一个仍可登录的管理员；唯一管理员也无法登录时，此流程无法恢复。当前没有绕过管理员身份验证的恢复入口，也未实现邮件或短信自助找回。建议保留另一个可信管理员账号。

## 查看操作记录

管理员在用户中心打开「操作记录」，按操作人或目标用户名搜索。每页 50 条，按写入顺序由新到旧展示时间、操作类型、说明、操作人与目标账号。

| 记录类型 | 记录内容 |
| --- | --- |
| 创建账号 | 本机管理员初始化、开放注册或通过邀请码注册 |
| 调整账号 | 角色和启用状态变更 |
| 修改或重置密码 | 正常修改、签发重置码、使用重置码完成恢复 |
| 注册设置 | 开放注册和邀请码必填策略变化 |
| 访问设置 | 是否必须登录用户账号才能访问资料库 |
| 邀请码 | 生成数量、使用限额、有效天数，或停用码的末尾标识 |
| 登录设备 | 从设备管理中退出当前、指定或其他全部设备 |

使用重置码完成恢复时，操作人显示「通过重置码验证」，目标显示恢复的用户名。其他操作记录发起账号的用户名快照。

只记录上述成功的关键操作，不记录登录失败、资料编辑、普通退出按钮等全部活动。实际无变化的角色/设置保存、重复停用及撤销零个设备不会新增记录。数据库升级前的历史操作不回填。

操作记录不包含密码、token、完整邀请码、完整重置码、原始请求正文、IP 或 User-Agent。记录表保留最近 10,000 条，较早记录自动删除；它是管理追踪功能，不是不可篡改的审计归档。记录与对应变更在同一事务内写入，记录写入失败时变更一并回滚。

## 接口与存储

路径前缀为 `/api/accounts`，写请求只接受 JSON。账号、会话及注册策略的一般规则见[用户账号与登录设备](user-accounts.md)。

| 方法与路径 | 输入 | 成功响应 |
| --- | --- | --- |
| `POST /admin/users/:id/password-reset` | 管理员会话、currentPassword（操作者密码） | 201：reset，含 username、code、expiresAt |
| `POST /password/reset` | username、resetCode、newPassword | 200：ok；不返回 token |
| `GET /admin/audit` | 管理员会话；可选 search、offset | events、total、offset、limit |

`expiresAt` 和记录的 `createdAt` 是 Unix 毫秒。events 每项包含 id、action、actorUsername、targetUsername、summary、createdAt。

无效用户名/重置码组合、已消费或过期的码统一返回 400，不区分具体原因；不能据此查询账号是否存在。弱密码单独返回输入错误。签发停用账号的码返回 409，非管理员返回 403。签发和使用分别按真实 TCP 来源限流，每 15 分钟最多 20 次；达到限制返回 429 和 Retry-After。

账号数据库 schema 3 引入 `account_password_resets` 和 `account_audit`，当前 schema 4 额外保存[账号访问要求](account-access.md)。旧版自动升级并保留用户、密码和有效会话。重置码表每个用户最多一条，后台只保存 SHA-256 摘要；过期行会在后续签发时清理。

## 验证证据

`npm run verify:accounts` 在临时 SQLite 和动态端口 HTTP 服务中覆盖管理员二次验证、码与账号绑定、过期与替换、并发消费、所有会话撤销、事务回滚、记录脱敏及保留上限、限流和版本 2 升级。

浏览器 fixture 操作实际共享表单及 Android 适配层，覆盖错误反馈、管理员发码、网页恢复后登录、Android 保留失效凭据直到显式恢复、清理原生会话后重新登录、操作记录搜索和移动端布局。截图只包含临时测试账号和已失效的码。

这类验证不启动真实主服务、不接触真实账号库，也不等同于 APK 真机安装或服务部署。
