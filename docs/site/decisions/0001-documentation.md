# ADR 0001：单一正文，多种阅读入口

状态：本次文档实现采用。日期：2026-08-30。

## 背景

项目已经有一批专题文档，但缺少统一站点和按任务阅读的 AI 入口。
其中部分内容记录本机部署事实、历史方案和较长的接口清单。
项目业务代码正在持续变化，文档工具不应干扰应用依赖或自动公开运行材料。

## 决策

- 使用 VitePress 生成静态网站，适配 GitHub Pages。
- 依赖与锁文件单独放在 `docs/`，根应用包保持不变。
- `docs/site/` 的 Markdown 为唯一正式正文；以显式导航清单决定发布范围。
- 通过同一生成器导出逐页 Markdown、短索引、完整正文、元数据与分节检索索引。
- 根 `AGENTS.md` 保持短小，指向具体文档，不在其中复制完整架构。
- 元数据记录来源和人工核对日期；构建检查链接、产物一致性和发布范围。

## 取舍

独立精选目录意味着旧文档需要逐篇迁移，初版不会自动公开所有细节。
它降低了旧结论进入 AI 上下文以及本机资料被打包的风险。

静态站不提供服务端问答；它不需要模型密钥或向量服务。
使用者可以按需将 Markdown 或分节索引接入自己的检索工具。
当前采用来源路径和日期追溯，不自动判定源码语义变化；维护者仍负责内容复核。

文档使用稳定版 VitePress 1.6.4。它声明的 Vite 5 依赖存在已知漏洞，
本包通过局部 override 固定 Vite 6.4.3；当前 Vue 插件接受 Vite 6。
这个兼容修复需要保留构建、搜索、预览与依赖审计的验证，升级 VitePress 时重新评估是否可移除 override。
本地预览使用 Vite 的 preview API 显式绑定 loopback；VitePress 1.x 自带预览器不会使用传入的 host 参数。

## 后续演进条件

| 新需求 | 再考虑的方案 |
| --- | --- |
| API 有统一、可验证的 schema | 从 schema 生成接口页或 OpenAPI |
| 多版本文档有明确用户 | 添加版本导航、固定源码引用与兼容路由 |
| 检索规模和真实需求增长 | 增量索引与外部检索服务 |
| 需要更多语言 | 明确维护责任后引入翻译流程 |

不要为了“AI 项目”这个名称预先引入这些系统。
先保持当前文档可读、可定位、可构建，并让代码变更同时更新相关知识。
